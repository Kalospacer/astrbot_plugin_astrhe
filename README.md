# AstrHe

![AstrHe](logo-full.png)

> 氦产生光与热，光热于是便有了构造生命的使命，而生命的使命，便在于孕育灵魂，而每个独特的灵魂，都将以生命为载体，构建独特的光与热。

**AstrHe**（He，氦）是一款 AstrBot 插件，主题是「灵魂」：让 bot 拥有自己的想法——每天零点在后台复盘当天所有聊天，自己想清楚接下来要做什么、为什么做、怎么做，写成规划书和待办，并给自己定好闹钟；白天聊天时带着这份计划；闹钟到点时主动去做。

## 它每天做什么

- **白天**：悄悄记录聊天账本（文字消息、bot 自己的回复、戳一戳、贴表情、撤回、进退群、好友申请），聊天时把属于这个会话的待办和规划段落临时注入请求（不写进对话历史）。
- **零点**：补拉聊天历史 → 每个会话派一个只读汇报子代理 → 主 agent 汇总写规划书、待办、闹钟卡片、关系本更新、承诺跟进 → 1 至 2 个审稿子代理复盘 → 一次性提交。**全程无感：夜间不会向任何会话发送任何消息。**
- 计划有变化时，夜间主 agent 可以撤销尚未执行的闹钟；改期或改内容通过「取消旧闹钟＋新建」草稿一起审稿、提交，提交时先取消再新建。
- **到点**：闹钟走 AstrBot 自己的定时任务系统，面板里照常可看、可改、可立即执行。每个闹钟都带着完整的「来龙去脉卡片」。

## 设置项

共三个：

| 设置 | 说明 |
|---|---|
| `enabled` | 总开关，默认关闭 |
| `provider_id` | 夜间复盘使用的模型；留空用 AstrBot 当前默认的聊天模型 |
| `persona_id` | 夜间分身共用的人格，从 AstrBot 已有人格中选择；留空或所选人格不存在时回退默认人格 |

## 指令（仅管理员）

- `/astrhe run`：立即运行一次夜间复盘并提交（后台执行）
- `/astrhe dryrun`：演练一次，不提交
- `/astrhe status`：最近一次运行的摘要；运行中显示当前阶段与已用时长
- `/astrhe stop`：停止正在进行的运行（提交前停止判失败，提交后外部动作照常收尾）

## 白天新增的 LLM 工具

`astrhe_todo_update`（勾选待办，备注会回流次夜复盘）、`astrhe_read_plan`（翻规划书）、`astrhe_schedule`（增强定时工具，替代自带 future_task，支持指定目标会话）、`astrhe_qq_lookup`（QQ 只读查询）、`astrhe_qq_act`（贴表情、戳一戳、点赞、改签名与在线状态，均带频率上限）。

`astrhe_schedule` 的 `expect_friend_ids` 可由管理员标记预期联系人并当场处理已有申请；重复闹钟仅管理员或夜间主 agent 可创建，相邻至少 1 小时，深夜需约定理由。

## 隐私说明

- 插件会在本地保存 **30 天**的文字聊天记录（群聊与私聊），只存在插件自己的数据目录，不写进日志。
- 好友申请记录随聊天账本按 **30 天**保留期清理。
- 夜间复盘会读取这些记录并发送给你配置的模型提供商——**夜间会消耗不少 token**，请留意账单。
- 撤回的消息会被标记并从夜间素材中排除。
- 规划中标记了保密对象的内容，在保密对象在场的会话里会被遮挡。
- 保密闹钟的面板描述使用中性文字；目标是群聊或保密对象本人的私聊时，总结只写「已完成」。帮手私聊等其他目标会保留实际发送内容和发送结果，便于后续接话；总结不得复述卡片背景、保密对象或禁忌。管理员仍可查看会话历史，完整的惊喜查看模式尚未提供。

## 已知限制

- 只支持 **aiocqhttp**（NapCat）平台。
- 开发与测试基于 **AstrBot 4.29.0-beta.1**，不限制安装版本；其他版本尚未验证。
- 如果 AstrBot 配置了 `id_whitelist`，陌生人的好友申请会在 Whitelist 阶段被拦下，插件收不到，自然也无法自动同意。
- 流式回复、`send_message_to_user`、闹钟唤醒等路径发出的 bot 消息，要等夜间补拉才能进账本。
- 夜间运行不设时长、步数或复盘窗口数据量上限，始终使用流式请求。模型请求失败时保留已完成的对话和工具结果，等待 30 秒重试；连续 3 次失败才终止，中间成功一次就重新计数。模型请求超时与外部工具超时沿用 AstrBot 设置。
- 提交前终止不会应用草稿，白天沿用上一份计划；提交后发生模型错误或人工停止，已提交的计划保留，外部动作照常收尾。可以用 `/astrhe stop` 人工停止。
- 汇报、规划与白天注入的字数只作建议，不做硬截断；每页/每块大小只决定读法，不减少内容。内容较多时会增加 token 消耗。
- 查看页前端暂未提供，本版仅包含后端 Web API。
